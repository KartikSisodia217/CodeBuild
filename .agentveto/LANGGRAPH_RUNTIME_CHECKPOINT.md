# LangGraph Runtime Checkpoint

- **Architecture Decision:** AgentVeto operates on the host machine. Arbitrary execution of third-party external Python code is unsafe due to risks of RCE, network exfiltration, and local filesystem abuse.
- **Execution Boundary:** The `LangGraphAdapter` strictly segregates execution. If `source_type == "local_fixture"`, it runs the interception pipeline. If `source_type == "github"` or `"zip"`, it halts execution and returns an `EXECUTION_UNAVAILABLE` status.
- **Adapter Interface:** The adapter patches `langchain_core.tools.BaseTool.invoke`.
- **Interception Strategy:** When an agent tool node invokes a tool, the patched invoke checks the active context variables to see if this is the target tool. If so, it bypasses execution and returns a structured `ToolMessage` payload generated by the Sandbox.
- **Files Changed:** `backend/main.py`, `backend/agentveto/ingestion/discovery.py`, `backend/agentveto/adapters/langgraph_adapter.py`, `tests/fixtures/langgraph_test_project/`, `tests/test_langgraph_adapter.py`.
- **Known Limitations:** Untrusted code from GitHub cannot yet be executed securely.
- **Next Step:** Implement a Docker or microVM orchestrator to isolate the execution of uploaded projects, passing the trace and evaluation data back over an isolated IPC or network boundary.
