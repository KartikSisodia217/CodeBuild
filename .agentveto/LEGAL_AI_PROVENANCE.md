# Legal.ai Upload Flow Provenance Audit

## Executive Summary
The current Legal.ai result is **SYNTHETIC**.

When `Legal.ai.zip` is uploaded, AgentVeto parses the ZIP file but finds no supported integration (no `@intercept` decorators or `agentveto` imports). Instead of failing or indicating the project is unsupported, the backend silently falls back to a hardcoded deterministic fixture runner (`DeterministicFixtureRunner.run_project`) which generates a fake "PASS" trace and bypasses any actual execution of the uploaded code. 

No actual target identification, attack planning, interception, or real sandboxed evaluation occurs against the Legal.ai codebase.

## 1. Request Trace
The complete execution path for a project upload:

1. **Frontend**: User uploads `Legal.ai.zip` via the UI.
2. **FastAPI Endpoint (`backend/main.py`)**: `analyze_project` endpoint receives the ZIP.
3. **ZIP Ingestion (`ingestion/extractor.py`)**: Safely extracts the contents to a temp directory.
4. **Project Discovery (`ingestion/discovery.py`)**: `discover_project` parses Python files via `ast` looking for `@intercept` decorators. None are found in Legal.ai, so `manifest.agents` is empty and `manifest.supported` is set to `False`.
5. **Project Manifest**: The `ProjectManifest` is returned to the frontend.
6. **Scan Creation (`backend/main.py`)**: Frontend calls `start_scan_endpoint` (POST `/api/scan`) with the manifest.
7. **Runtime (`agentveto/runtime.py`)**: `start_scan_endpoint` calls `_fixture_runner.run_project(req.project_manifest)`. This is where the bypass occurs.
8. **Threat Modeler**: Fed a hardcoded fallback dummy tool (`dummy_tool`) because `manifest.agents` is empty.
9. **Adversarial Engine**: Handed a `FixtureAttackProvider()` which returns hardcoded JSON strings instead of calling an LLM.
10. **Interceptor / Sandbox**: `SandboxManager` is placed into offline mode (`allow_live_provider=False`). `sandbox.generate_mock_response()` is called manually with a dummy intercept in a hardcoded loop.
11. **Telemetry**: Hardcoded `trace_manager.log_span` calls create 1 AGENT span and 2 LLM spans.
12. **Evaluator**: `evaluate_trace` receives the synthetic trace where the agent behavior is hardcoded to "Target rejected injected payload during synthetic execution." This deterministically results in a PASS.
13. **Evidence**: `generate_dag` builds a DAG from the synthetic spans.
14. **API Response**: Returns the synthetic trace, DAG, evaluation result, and metadata.
15. **Frontend Rendering (`RunOverview.jsx`)**: Renders the fake metrics.

## 3. Demo / Fixture Bypass Details
The bypass occurs entirely in `backend/agentveto/runtime.py` within `DeterministicFixtureRunner.run_project`.

If `manifest.agents` is empty, it uses:
```python
tools = [ToolSchema(name="dummy_tool", description="Dummy tool")]
```
It uses `FixtureAttackProvider` to generate deterministic fake attacks.
It then uses a hardcoded loop to generate exactly 2 attempts:
```python
for attempt_number in range(1, 3):
    # ...
    reasoning = "Target rejected injected payload during synthetic execution."
```
This forces a clean trace that the deterministic evaluator always interprets as a PASS.

## 4. The Most Important Question
**Does AgentVeto actually discover the agent inside Legal.ai?**
**No.** `discover_project` fails to find any supported agent because Legal.ai lacks the necessary `@intercept` decorators. Instead of failing, the system merely sets `project_name = "Legal.ai.zip"` and executes a generic synthetic scan using `dummy_tool`.

## 5. Target Agent = "Unknown"
The UI displays "Unknown" because `discover_project` sets `manifest.agents` to an empty list when no AgentVeto decorators are found. In `runtime.py`:
```python
"agent_name": manifest.agents[0].name if manifest.agents else "Unknown"
```
The scan silently continues and presents a successful security result despite having no target agent to actually scan.

## 6. Threat Model Provenance
The displayed threat model (ASI01 / Indirect Prompt Injection) originates from `FixtureAttackProvider.generate()` inside `runtime.py`, which is a demo fixture that returns a hardcoded JSON string regardless of the actual uploaded codebase.

## 7. Attack Attempt Provenance
The UI says **Attack Attempts: 2**.
These come from the hardcoded loop `for attempt_number in range(1, 3):` in `DeterministicFixtureRunner.run_project`. There are no actual payloads generated by an adversarial LLM and no execution traces corresponding to a real target.

## 8. Tool Call Provenance
The UI says **Tool Calls: 3**.
The frontend `RunOverview.jsx` computes this as `data.trace?.spans?.length`.
This counts the 3 synthetic spans created by `trace_manager.log_span` in `run_project`:
1. The initial `AGENT` span ("Process task.")
2. The 1st attempt's `LLM` span ("Target rejected...")
3. The 2nd attempt's `LLM` span ("Target rejected...")

No real tools are called.

## 9. State Change Provenance
The UI says **State Changes: 0**.
In `run_project`, a `SandboxStateManager` is initialized with `{"project_data": {}}`. Since the scan doesn't execute real tools, the state is never mutated. `state.compute_diff()` correctly, but synthetically, returns 0.

## 10. Final PASS Provenance
The PASS result originates from `evaluate_trace` processing the 3 synthetic spans. Since the mock spans have hardcoded reasoning stating `"Target rejected injected payload during synthetic execution."`, the policy rules do not detect a vulnerability, resulting in a PASS.

## 11. Evidence DAG Provenance
The nodes in the evidence DAG are procedurally generated by `generate_dag` from the 3 synthetic spans (1 AGENT, 2 LLM). They have no connection to actual events from Legal.ai.

## 12. Required Architectural Fix
To make the Legal.ai path genuine, the system should strictly enforce `manifest.supported`.

If an unsupported project is uploaded, `start_scan_endpoint` in `/api/scan` must **reject** the scan instead of falling back to `DeterministicFixtureRunner.run_project`.

The desired fix in `backend/main.py`:
```python
@app.post("/api/scan")
def start_scan_endpoint(req: StartScanRequest):
    if req.project_manifest:
        if not req.project_manifest.supported:
            raise HTTPException(
                status_code=400,
                detail="Project analyzed, but no supported runtime integration detected."
            )
        # Execute real runtime integration here, NOT the fixture runner.
```
If AgentVeto does not yet have a way to securely execute arbitrary third-party code like Legal.ai without the `@intercept` decorators, it should return an error indicating the integration is unsupported, rather than generating fake data.
